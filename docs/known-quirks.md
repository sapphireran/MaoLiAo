# Known quirks

Personal notes from reading the 2.0 tree. None of these are changed by the docs/examples pass; the EasyX game is left as it was.

## Headers

### `MYDEFINE` vs `MYDIFINE`

`define.h` opens with `#ifndef MYDEFINE` and then `#define MYDIFINE`. The include guard never defines the name it tests. The header is still safe in practice because of `#pragma once` on the first line. A second include in a TU that ignored `pragma once` would re-define every macro.

### `LIFE` and `F` swallow a semicolon

```cpp
#define F TIME*0.3;
#define LIFE 5;
```

`int life = LIFE;` expands to `int life = 5;;`. `scenery_iframe += F;` expands to `scenery_iframe += TIME*0.3;;`. Harmless. `if (life == LIFE)` would become `if (life == 5;)` and fail to compile — the project never writes that.

### Duplicated `Map`

`role.h` and `scene.h` each contain a full `struct Map` behind `#ifndef _MAP`. They match today. Adding a field in only one header would desync layout if both translation units saw different definitions — ODR territory.

## Copy loops that walk one past the array

`createCoin`, `createFood`, `createEnemy`, and world 3 `createMap` use

```cpp
while (i <= sizeof(arr) / sizeof(arr[0]))
```

The last iteration reads an element that was never initialised (and, for world 3 maps, writes `map[30]` when `MAP_NUMBER` is 30). Worlds 1–2 map copies use `id > 0 && id < 15 && i < MAP_NUMBER`, which is the correct bound, but they still **drop** authoring that does not fit.

`examples/src/map_layout.cpp` recounts the authored rows and prints what the 30-slot cap keeps.

## World 2 comment already flags it

```cpp
while (m[i].id > 0 && m[i].id < 15 && i < MAP_NUMBER)//???存在问题
```

The author saw the overflow. The colliding staircase still fits; the victory sign and trees do not. Gameplay uses `isEnding` rather than the sign, so a clear still works.

## `_kbhit` vs `GetAsyncKeyState`

`getKey` only resamples the async bitmask when the **console** reports a key. The stored `Control::key` is otherwise sticky. Combined with pause virtual bits that remain in `key` until another `_kbhit`, a `VIR_RESTART` can be seen for more than one frame. `main` rebuilds `Role`/`Scene` each time it sees that value, so a sticky restart would reconstruct twice — usually invisible.

## World 3 death uses the live `world`, walls do not

```cpp
hitMap(x, y, scene, world);     // vertical / contact — can kill in world 3
hitMap(x, y, scene, 1);         // horizontal rewind, enemies, bullets — never kills
```

A flap into a pipe kills. Walking sideways into the same pipe, the wall test passes `1` and only rewinds `x`. Depending on the next vertical probe, you may still die on the following tick.

## Food units are inconsistent

Worlds 1–2 store pixels. World 3 stores `{10, 10}`. `hitFood` never multiplies by `WIDTH`. `setScorePos` always treats the pair as tiles when drawing the burst, so a world-1 pickup at `(448, 160)` would spawn a pop at tile (448, 160) — far off-screen — if that path is hit. Coins (true tiles) pop correctly.

## Release / Unicode

`MaoLiAo.vcxproj` sets `CharacterSet` to `MultiByte` for Debug and `Unicode` for Release. Narrow `"黑体"` / `"得分:  "` literals in `control.cpp` are wrong for a Unicode build (`outtextxy` expects `TCHAR*`). Debug is the configuration the project was developed against.

## `max` and `random` macros

`define.h` defines `max(a,b)` and `random(a,b)`. Windows headers also provide `max` when `NOMINMAX` is unset. World 3 includes `<math.h>` after the game headers in some TUs and uses `max` for pipe lengths. Build order has been lucky.

`random` is `rand()%(b-a)+a` with no `srand`. World 3 pipes are a fixed sequence per CRT.

## Unreachable shutdown

```cpp
while (true) { ... }
mciSendString("close all", ...);
closegraph();
```

The title-screen 退出 path calls `exit(0)` and skips both. There is no in-loop break.

## `Inertia.cpp` starts with `#pragma once`

That pragma is meaningless in a `.cpp`. Harmless.

## Hero spawn `y`

```cpp
myHero.x = X0;   // 64
myHero.y = X0;   // also 64 — Y0 exists (96) and is unused
```

The cat starts at `(64, 64)`, not `(64, 96)`. `Y0` is dead.

## Bullet flight from `show`

`bullteFlying` (typo) runs inside `Role::show`, not `action`. If something drew twice in one tick, bullets would step twice. `main` draws once.

## Score type vs HUD width

`score` is `int`. `_itoa_s(score, s2, 10)` writes into `char s2[5]`. A score of `10000` overflows that buffer. Practical runs stay in two digits (a full coin sweep is well under 200).

## Checked-in `gameRecord.dat`

The working-tree save is a leftover play session. It is not generated by the examples. Loading it on a machine without a matching `res\` still only sets `world`.

## Include guard in the portable model

The examples use `#pragma once` and a proper `MAOLIAO_MODEL_HPP` guard so they do not repeat the `MYDIFINE` typo. They also use `<` — not `<=` — on every copy loop.
